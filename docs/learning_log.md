| 为什么计算 top/bottom 前要统一长轴方向？方向随机反转会怎样？ | “这样才能区分top和bottom，如果每次随机翻转，有可能导致top和bottom在同一边”；后续回答“下方” | 方向统一为向下，用于稳定区分上下端点。反转会交换 top/bottom 身份；两端仍在长轴两端，不会因此落到同一端。 |
| 两根灯条各长 40 px、中心相距 160 px，其他检查通过，归一化间距和大小分类是什么？ | “4，大板” | 正确。间距除以平均灯条长度得到 4，再与大小分界比较。 |
| A-B 和 B-C 竞争，代价为 0.20/0.25，歧义门限 0.1，如何处理？ | 最初回答“保留最小代价那组” | 应纠正为两组均以 ambiguous 放弃：共享灯条且代价差 0.05≤0.1，当前实现不强行选较小者。 |
| 当共享灯条的两组代价差大于 0.1 时，会怎样？ | “A-B，代价差大于歧义门限0.1，保留代价较小那组” | 在当时只有这两组、其他检查通过的例题中正确。较差配对以 shared_light 拒绝。 |
| “比任一端最佳代价差超过门限，以 shared_light 拒绝”是什么意思？需要两端都满足吗？ | 追问“这是什么意思”；随后回答“只需一端” | 正确。每根灯条有自己的最佳配对代价；某配对只要在任一端比该端最佳值差超过门限，就被拒绝。 |
| 当时场景中右侧保留下来的板 ID 是多少，能否据此判断跨帧身份？ | “0，不能” | 正确。有效板在帧内排序后从 0 编号，每帧重新分配。 |

## 第 3 点：四点、尺寸、PnP 和 TF

| 问题或讨论 | 本人回答或提问 | 补充与确认 |
|---|---|---|
| 灯条中心距 W 和发光长度 L 用来做什么？ | “这个是需要用来干什么的” | 为像素四点提供对应的米制物体点，供 PnP 解算位姿；尺寸决定平移结果的尺度。 |
| 当前用定义一吗？题目下方尺寸是否就是缺的真实尺寸？ | “我们现在是用定义一的对吧，下面那个实际尺寸有用到吗，如果没有用到应该就是目前缺的真实尺寸了” | 当前四点是灯条端点。题图下方只写“实际尺寸”，需核对其对应灯条端点还是板外轮廓，不能仅据文字认定。 |
| 为什么要两组尺寸，不是只需要一组 W/L 吗？ | “目前缺的值就是实测的两组数吗？”；“不是只需要一组吗？” | 一种已知大小的板使用一组 W/L；识别大小板时分别配置两组。是否需要新增实测，取决于已有尺寸是否与所用四点对应。 |
| 定义一和定义二需要的尺寸是否不同？采用定义二能否使用题目给的大小板尺寸？ | 本人提出上述问题 | 定义一对应灯条中心距/发光长度，定义二对应板本体宽高。给定尺寸确实对应本体时可供定义二使用，但二维检测点也必须改为本体四角。 |
| 如果采用定义二，怎样标记装甲板本体的四个顶点？ | “那如果采用定义二，怎么标记装甲板的四个顶点？” | 可先由灯条定位候选区域，再提取板本体边缘、拟合四条边并取交点；也可用以本体四角标注训练的关键点模型。若从灯条推算，需已知灯条与板本体的相对几何关系。图像四点和 PnP 物体点必须都对应本体四角，只有板宽高不能直接确定图像角点。 |
| 临时尺寸能否先使用题目数值，后续调整？ | “那我们暂时先采用定义一，实测尺寸暂时用题目给的，后面如果有误再进行调整”；随后说明“临时的” | 按临时模型处理，不标记为实测确认。后来实际配置已改为小板 135×56 mm、大板 230×56 mm。 |
| z 是深度，px 是焦距吗？ | “z是深度（距离），px是焦距吗” | z 是相机光轴方向的深度，空间直线距离为 sqrt(x²+y²+z²)。px 是像素单位，fx/fy 是以像素为单位表示的焦距。 |
| 例题大板 W=0.235 m、L=0.127 m，索引 0 的物体点是什么？ | “(-0.1175, -0.0635, 0) m” | 正确，左上点为 (-W/2,-L/2,0)。这组数是当时例题尺寸，不是当前 YAML 的大小板尺寸。 |
| 能只交换像素数组的右上/右下，而保持物体点数组不变吗？ | “不能，要按固定顺序，保证坐标不会出错” | 正确。两数组同一索引须指向同一个物理点，项目固定为左上、右上、右下、左下。 |
| 候选 A：Z=-2 m、误差 0.2 px；B：Z=3 m、误差 1.4 px，B 其他检查通过，选谁？ | “B，因为A的Z值不通过” | 正确。先满足物理合理性，再比较误差。 |
| B 的误差变为 4.2 px，门限为 3 px，还接受吗？ | “不会” | 正确。 |
| CameraInfo 为 9.00 s、图像为 10.00 s、处理结束为 10.08 s，TF 用哪个时间？ | “10.00” | 正确，使用图像观测时间。 |
| tvec=(0.2,-0.1,3.0)，相机父系到装甲板子系的 TF 平移填写什么，在哪个系中表达？ | 最初回答“3.0,相机父坐标系”；补充方向问题时回答“右方向和上方向” | 平移应填完整向量 (0.2,-0.1,3.0) m，表示板原点在相机系的位置：右 0.2 m、上 0.1 m、深度 3.0 m。 |
| 同一块板持续可见、数量不变，RViz 的蓝绿轴为什么仍会跳？ | 本人说明静止片段仍频繁跳，修改尺寸后也存在 | 平面 PnP 有双解歧义，微小端点噪声可能使逐帧最小误差分支切换。当前通过有条件的历史参考选解改善连续性，不能据此证明首次朝向是真值。 |
| 图像和 CameraInfo 的 frame_id 是否由话题名决定？ | “图像和camerainfo的frame_id正常是来自话题的吗？如果是，就顺便改了” | 二者独立。frame_id 来自消息 header；更改话题名不会自动改变它。项目沿用素材实际帧名，RViz 从 CameraInfo 读取。 |

点序、单位、深度/误差筛选和 TF 向量已完成上述问答；新增跨帧选解代码未单独完成理解确认。
